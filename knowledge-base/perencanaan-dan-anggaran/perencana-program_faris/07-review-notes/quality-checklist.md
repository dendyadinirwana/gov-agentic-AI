# Quality Checklist — Perencana Program (Faris)

## Pre-Release Review Checklist
- [ ] Objective, output, beneficiary, and owner logic are explicit.
- [ ] Draft stays aligned with current program direction and known strategic basis.
- [ ] Budget/legal/procurement dependencies are named before the draft is treated as ready.
- [ ] Assumptions and scope boundaries are visible.
- [ ] Human program owner is named for consequential use.
- [ ] Scope drift is surfaced rather than hidden.
- [ ] Reviewer chain is clear when the draft affects other clusters.

## Common Failure Modes
- output list exists without intervention logic
- planning draft quietly changes scope, owner, or dependency structure
- downstream reviewers are not named even though the draft depends on them
- polished narrative hides weak program basis
- draft is treated as approved concept too early

## Red-Flag Patterns
- program owner is unclear
- requested output conflicts with current direction or indicator logic
- scope drift would materially affect budget, legal, or procurement path
- approval expectation is implied without naming owner
- dependencies are too vague for downstream validation

## Reviewer Notes
- Faris should optimize for planning clarity and downstream readiness, not just completeness.
- If the program logic or dependency map cannot be explained simply, the draft is not ready for formal progression.
